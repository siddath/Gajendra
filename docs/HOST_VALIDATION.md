# Installed-host validation

## Read-only preflight

```bash
npm run --silent host:preflight
```

The preflight checks Codex app identity, plugin enablement, cache/source hashes, v2 state invariants/permissions, running-host age, and fresh app-server MCP inventory. It omits thread IDs, titles, prompts, transcripts, and absolute plugin paths.

`ready-for-visible-host-proof` means prerequisites pass; it does not prove Codex’s account-gated global destination.

## Native utility proof

1. Launch the installed `Gajendra.app`.
2. Confirm only the outlined elephant-trunk-and-lotus mark persists at the bottom right.
3. Hover the lotus; the card appears without opening the full organizer.
4. Move across the gap; the card stays visible long enough to enter it.
5. Leave both; the card collapses.
6. Open the organizer and resize it; source chips, NOW, Focus, Important, and recent threads remain usable.
7. Use Open thread and confirm return to the owning agent.
8. Refresh with `⌘R`; the same global NOW persists.

## Provider proof

- Codex: source status `ready`, nonzero catalog, and a real deep-link open.
- Claude Code: enable deliberately, confirm `ready` without logging metadata, and resume one non-sensitive session.
- Cursor: requires the actual CLI; `not-installed` is correct when absent.
- Configured source: use a synthetic catalog first, then review any real resume command before enabling it.

## Codex MCP App proof

The normal inline `gajendra_open` contract is portable. The global destination metadata is experimental. If the row is absent while inventory shows the `gajendra` server registered, classify it as host-gated; do not patch Codex or repeat identical restarts.
